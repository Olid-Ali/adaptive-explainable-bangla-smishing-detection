# User Study Codebook

*Preliminary qualitative codebook built from the free-text responses currently in `full_survey.xlsx`. Only the **No Explanation** condition has completed responses so far (n = 11); the **Simple** and **Moderate** condition sheets are still empty. Codes and frequencies below reflect this initial batch only and should be expanded/revised as more responses come in.*

---

## Codebook of User Feedback
*(Derived from Q19 — "Did the system help you make better decisions?" and Q20 — "Did the information match your technical/cybersecurity knowledge?")*

| **Code** | **Code Description** | **SubCode** | **SubCode Description** | **Freq.** | **Examples** |
|----------|----------------------|------------|-------------------------|---------|------------|
| **Perceived Decision-Making Benefit** | Whether users felt the system's output helped them judge SMS legitimacy more effectively. Includes both unqualified endorsements and endorsements tied to specific system features. | **General positive endorsement** | Simple affirmative response with no elaboration on why the system helped. | 2 | "Yes" <br> "Yes" |
|  |  | **Helpfulness attributed to specific features** | Users cite concrete elements — flagged links/senders, confidence scores — as the reason the system helped. | 2 | "Yes, it was very helpful. The system clearly flagged suspicious links and sender details, which made it easy to quickly spot fake or smishing messages and avoid potential scams." <br> "Yes, it clearly showed me with their predicted confidence score." |
|  |  | **Helped via clarity of information** | Users credit the understandability of the presented information for the benefit. | 1 | "Yes because those information was easy to understand" |
|  |  | **Qualified / uncertain endorsement** | Users express partial or hedged agreement that the system helped. | 2 | "Yes, maybe" <br> "Maybe, but they didn't interpret the messages" |
| **Self-Sufficiency / Limited Reliance on AI** | Users feel they can judge SMS legitimacy on their own and see limited added value from the AI system. | | | 2 | "I won't relay on AI to detect whether it is spam or not, I can do it by myself and I'm 100% confident about that" <br> "It was easy to detect. System didnt helped me" |
| **Lack of Explanation Reduced Perceived Helpfulness** | Users note that the absence of explanatory detail limited the system's usefulness — expected in the No Explanation condition. | | | 1 | "not that much, no explanations were given" |
| **Technical Content Matched User's Background** | Users with existing technical/cybersecurity or ML knowledge felt the system's information was pitched at an appropriate level. | | | 2 | "Yes. I faced that situation already" <br> "Yes, i know about the ML things." |
| **Detailed Technical Metrics Appreciated** | Users specifically valued granular technical detail (e.g., URL structure, domain age, threat flags) as matching their knowledge level and being actionable. | | | 1 | "Yes, it matched well. The technical metrics—such as URL structure, domain age, and threat flags—provided actionable insights without clutter, allowing me to evaluate the SMS security risks quickly and effectively." |
| **Content Perceived as Too Basic** | Users felt the information shown was simpler than their own knowledge level. | | | 1 | "No, it was easy. Simple thing" |
| **Partial / Uncertain Match with Knowledge Level** | Users gave a hedged answer about whether the content matched their technical background. | | | 2 | "slight, i would say" <br> "maybe" |
| **Baseline Smishing Awareness** | Responses to the optional "What do you know about smishing?" question, describing users' pre-existing understanding of smishing before the study. | **Accurate baseline understanding** | User demonstrates a correct, if brief, understanding of what smishing is. | 2 | "one kind of cyber attack, where attacker use mobile sms for attack" <br> "Scam text messages designed to trick you into clicking bad links or stealing your personal information." |
|  |  | **No prior knowledge** | User indicates no familiarity with the term or concept. | 1 | "NO" |

### Notes on this draft
- Frequencies are drawn from the **No Explanation** condition only (n = 11 participants); several respondents gave "N/A" or single-word answers that weren't codeable and are excluded from the counts above.
- As response data comes in for the **Simple** and **Moderate** conditions, and once disagreement follow-up text is collected, codes should be re-checked for fit, merged/split as needed, and frequencies updated across the full sample.
